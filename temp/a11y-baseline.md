## Stage adjustments

The stage as the editor draws it defeats axe's contrast check, so the spec made two changes before every scan except the as-is pass.

1. It hid `.tabs-preview::after`, the editor's fade under the sticky preview band. axe treats any pseudo-element larger than a quarter of the text box in the background stack as unknowable and returns `incomplete` with `pseudoContent`. The fade spans the full band, so every text node in the stage came back incomplete.
2. It painted the stage with the theme's `--page-bg`. In its default mode `ShadowBackdrop` paints `--ui-surface-lowest` (`#050505`), an editor colour that no theme moves, so a preset sweep would measure every transparent component against near-black. `--page-bg` is the backdrop `measurePair` uses, which keeps the axe numbers comparable with `temp/contrast-checker-defaults.md`.

Under the default theme the as-is pass found 0 `color-contrast` violations and 285 incomplete, 285 of them `pseudoContent`. The adjusted pass found 7 violations and 58 incomplete. Every other rule reads the same in both passes. Wave 2 needs both changes, or an equivalent, before `color-contrast` reports anything.

## SIA-R65

Across the nine themes SIA-R65 evaluated 2061 tabbable targets inside the scope: 1944 passed, 0 failed, 117 came back cantTell. 0 scans hit an Alfa error.

Here SIA-R65 yields two outcomes, passed and cantTell. It compares each target's computed style with and without `:focus` across outline, box shadow, text decoration, colour, background and border, on the target, its descendants and its ancestors. When it finds a difference it passes. When it finds none it asks the question `has-focus-indicator`, and with no oracle to answer it the outcome is cantTell. A cantTell here means Alfa found no focus style.

**Matching.** The checker names token pairs and axe names DOM nodes with resolved colours, so the two meet on the component and the ratio. An axe violation matches a checker failure when the component is the same, the checker's role is text, and the two ratios differ by 0.02 or less. The checker truncates to two decimals and axe rounds to two. Each checker row counts once, however many nodes match it.

## Notes

### Engines and wiring

- SIA-R65 lives in `@siteimprove/alfa-rules`, and `Audit` in `@siteimprove/alfa-act`. The plan's install line and D5 name only `@siteimprove/alfa-playwright`, which depends on neither. The probe installed `@siteimprove/alfa-rules@^0.119.0` in the same `--no-save` command, and `alfa-act` arrived with it. Its minor version has to match the `alfa-dom` that `alfa-playwright` pins, 0.119 today. D5's list needs it.
- `Playwright.toPage` on the editor document cost about 2.5 s per scan. Nearly all of it went to auditing the editor's own controls, because SIA-R65 applies to every tabbable element in the document. The probe serialised the document with `@siteimprove/alfa-dom/native`, kept the head, the ancestor chain of the scope and the scope's subtrees, and built the Alfa page from that. The style sheets travel on the document node, so the cascade stays whole. A scan then cost 0.3 to 0.8 s, with identical outcomes on Button, TabBar and SideNavigation. Wave 1's `scanFocusVisible` needs the same pruning, which means calling the native serialiser directly instead of the adapter.
- axe's `include` scoping skips page-level rules, so `region`, `landmark-*` and `page-has-heading-one` never ran. They are outside the four WCAG tags in any case.
- No OKLCH misreads appeared. axe 4.14.0 reported resolved sRGB hex for every OKLCH token, and both overlapping ratios match the contrast checker to the hundredth.

### Contrast

- Only `color-contrast` moves with the theme. Every other axe rule and SIA-R65 report the same nodes under all nine themes, and the forced-colours pass reports the same non-contrast nodes as the default pass.
- Halloween, midnight-study and sunset paint gradient surfaces. Under those three axe returned about 160 `bgGradient` incomplete results each, against 30 under the other themes, and no `color-contrast` violation at all. The preset sweep gives no contrast verdict where gradients sit behind text.
- Button's shimmer `::before` is a full-size pseudo-element, so every Button text node returns `pseudoContent`, in every state and theme. Dialog's footer buttons inherit the same result. Hover states that paint a tint as a `background-image` return `bgGradient`, MenuSelect's hover item among them. These two blind spots cover most of the hover-text pairs the contrast checker flags.
- Editor content inside the stage paints `--ui-text-secondary` (`#bfbfbf`), an editor token that no theme moves: Card's "Content Placeholder" filler, Tooltip's demo targets, and the CodeSnippet editor's "Preview text" form label. It fails under the four light presets (autumn, ocean, sketchy, spring-meadow) and accounts for every preset `color-contrast` violation. Wave 2 has to exclude or retint the editors' own content in the stage, or these findings repeat on every run.
- The CollapsibleSection extra is also demo content: the editor's body paragraph sets `color: var(--text-secondary)` inline, which reads 3.38:1 on the open section's surface in the default theme. The contrast checker has no pair for it because the colour belongs to the demo.
- D6 scans the declared states under the contract's default view. Badge and CornerBadge open the Brand variant, Button opens Primary, and Notification opens Info, and none of their states selects another variant. Eight of the eleven failing text pairs in the contrast checker sit on variants the probe never rendered. Wave 2 needs to step through variants as well as states. The contracts' `properties` lists already name each variant and state pair.

### Forced-colours behaviour

- Under `emulateMedia({ forcedColors: 'active' })` Chromium computes `color: rgb(0, 0, 0)` and `background-color: rgb(255, 255, 255)` on every element in the stage. A read-back on Badge and Tooltip confirmed it. axe still reported the author's text colour on white, for example Badge brand `#ff75b1` on `#ffffff` at 2.49:1. axe pairs the unforced foreground with the forced background, so its forced-colours `color-contrast` results are false. The other rules and SIA-R65 matched the default pass node for node. As measured, a forced-colours rerun adds only false contrast findings. `a11y-forced-colors` in D1 needs a different check, such as border and focus survival, to earn a pass of its own.

### Focus visibility

- SIA-R65 passed Button, which declares no focus rule of its own. Chromium's user-agent `:focus-visible` outline counts, and Alfa models the user-agent sheet. The rule catches a component that overrides the outline without a replacement.
- SegmentedControl's selected segment paints its selected border as an `outline`, which overrides the user-agent focus ring, and declares no focus style. Focus on the selected option, the one a keyboard user tabs to, looks the same as no focus. This is a real gap.
- Input's error field: `.input-field.invalid .input-control:focus` holds the error outline, and the shipped config points `--input-focused-surface` and `--input-focused-text` at the same tokens as the default ones. Focus changes nothing visible on an invalid field. This is a real gap.
- Slider's thumbs set `outline: none` on `:focus-visible` and paint focus on the sibling `.cap`. SIA-R65 looks only at the target, its descendants and its ancestors, so it cannot see the cap. These cantTell results are probably false and need a manual look.

### Harness

- A theme preview lives only while the Theme Picker is open, and closing the picker cancels it. The picker's backdrop, `rgba(0, 0, 0, 0.65)` at z-index 9999, covers the stage, so axe would measure every colour through it. The probe hid the backdrop with CSS after each `previewTheme` and showed it again before `cancelThemePreview`. Wave 2 needs the same, or a harness method that previews a theme without the dialog.
- ImageLightbox's view opens its overlay, which covers the Theme Picker trigger, so the harness's real click landed on the overlay. The probe dispatched the trigger, row and Cancel clicks on their elements for that contract.
- The Theme Picker trigger sits below a 900 px viewport. A hit test has to scroll it into view first.
- Every declared state was reached. No `selectView` call failed.
- VideoFrame and VideoLightbox return `video-caption` as incomplete. axe cannot tell whether a video without a `<track>` needs captions.
